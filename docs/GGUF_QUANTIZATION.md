# GGUF와 양자화 기술 문서

## 1. GGUF란?

### 1.1 정의

**GGUF (GPT-Generated Unified Format)** 는 [llama.cpp](https://github.com/ggerganov/llama.cpp) 프로젝트에서 개발한 LLM 모델 파일 형식입니다. 기존 GGML 형식의 후속으로, 2023년 8월에 도입되었습니다.

### 1.2 왜 만들어졌는가?

```
기존 문제점:
┌─────────────────────────────────────────────────────────────────┐
│  HuggingFace 모델 (.safetensors, .bin)                         │
│  • Python/PyTorch 의존성 필수                                  │
│  • 메모리 사용량 높음 (FP32/FP16)                              │
│  • 배포 및 실행 환경 복잡                                      │
└─────────────────────────────────────────────────────────────────┘

GGUF 해결책:
┌─────────────────────────────────────────────────────────────────┐
│  GGUF 모델 (.gguf)                                             │
│  • C/C++ 네이티브 실행 (Python 불필요)                         │
│  • 양자화로 메모리 사용량 대폭 감소                            │
│  • 단일 파일로 모든 정보 포함 (self-contained)                 │
│  • CPU에서도 효율적 실행                                       │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 GGUF 파일 구조

```
┌─────────────────────────────────────────────────────────────────┐
│                        GGUF 파일 구조                           │
├─────────────────────────────────────────────────────────────────┤
│  Header                                                         │
│  ├─ Magic Number: "GGUF" (4 bytes)                             │
│  ├─ Version: uint32                                            │
│  ├─ Tensor Count: uint64                                       │
│  └─ Metadata KV Count: uint64                                  │
├─────────────────────────────────────────────────────────────────┤
│  Metadata (Key-Value pairs)                                     │
│  ├─ general.architecture: "llama" / "gpt2" / ...               │
│  ├─ general.name: 모델 이름                                    │
│  ├─ llama.context_length: 컨텍스트 길이                        │
│  ├─ llama.embedding_length: 임베딩 차원                        │
│  ├─ tokenizer.ggml.model: 토크나이저 타입                      │
│  ├─ tokenizer.ggml.tokens: 토큰 목록                           │
│  └─ ... (모델별 하이퍼파라미터)                                │
├─────────────────────────────────────────────────────────────────┤
│  Tensor Info (각 텐서의 메타데이터)                             │
│  ├─ Name: 텐서 이름                                            │
│  ├─ Dimensions: 차원 정보                                      │
│  ├─ Type: 양자화 타입 (F32, F16, Q4_K, ...)                    │
│  └─ Offset: 데이터 시작 위치                                   │
├─────────────────────────────────────────────────────────────────┤
│  Tensor Data (실제 가중치 데이터)                               │
│  └─ 양자화된 가중치 바이너리                                   │
└─────────────────────────────────────────────────────────────────┘
```

### 1.4 llama.cpp의 역할

llama.cpp는 **3가지 핵심 기능**을 제공합니다:

| 기능 | 설명 | 관련 파일 |
|------|------|----------|
| **형식 변환** | HuggingFace → GGUF | `convert_hf_to_gguf.py` |
| **양자화** | FP16 → Q4/Q8 등 | `quantize` (C++ 바이너리) |
| **추론 엔진** | GGUF 모델 실행 | `llama-cli`, `llama-server` |

## 2. 양자화(Quantization)

### 2.1 정의

**양자화**는 신경망의 가중치를 **더 적은 비트로 표현**하여 모델 크기와 메모리 사용량을 줄이는 기술입니다.

```
┌─────────────────────────────────────────────────────────────────┐
│  원본 가중치 (FP32 - 32비트 부동소수점)                        │
│                                                                 │
│  값: 0.123456789012345678901234567890...                        │
│  저장: [0][01111011][11111001101011100001010]                   │
│        부호  지수(8)      가수(23)                              │
│  크기: 4 bytes (32 bits)                                        │
├─────────────────────────────────────────────────────────────────┤
│  양자화 후 (INT4 - 4비트 정수)                                  │
│                                                                 │
│  값: 2 (0~15 범위로 매핑)                                       │
│  저장: [0010]                                                   │
│  크기: 0.5 bytes (4 bits)                                       │
│                                                                 │
│  → 8배 압축!                                                    │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 왜 작동하는가?

#### 2.2.1 가중치 분포의 특성

신경망 가중치는 대부분 **0 근처에 집중**되어 있습니다:

```
가중치 분포 히스토그램:

빈도
  ▲
  │         ████
  │        ██████
  │       ████████
  │      ██████████
  │     ████████████
  │    ██████████████
  │   ████████████████
  │  ██████████████████
  └──────────────────────▶ 값
     -2   -1    0    1    2

• 평균: ~0
• 표준편차: 작음 (보통 0.01 ~ 0.1)
• 이상치: 매우 드묾
```

#### 2.2.2 신경망의 내성(Robustness)

```
┌─────────────────────────────────────────────────────────────────┐
│  신경망이 양자화에 강건한 이유                                  │
├─────────────────────────────────────────────────────────────────┤
│  1. 과잉 파라미터화 (Over-parameterization)                    │
│     • 필요 이상으로 많은 가중치 보유                           │
│     • 일부 정밀도 손실이 전체에 미치는 영향 미미               │
│                                                                 │
│  2. 노이즈 내성 (Noise Tolerance)                              │
│     • 학습 과정에서 이미 노이즈에 노출됨                       │
│     • 작은 섭동에 강건하도록 학습됨                            │
│                                                                 │
│  3. 중복성 (Redundancy)                                        │
│     • 비슷한 역할을 하는 가중치가 많음                         │
│     • 하나의 정보를 여러 경로로 표현                           │
│                                                                 │
│  4. 활성화 함수의 비선형성                                     │
│     • ReLU, GELU 등이 작은 차이를 흡수                         │
│     • 출력은 입력의 작은 변화에 둔감                           │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 양자화 알고리즘

#### 2.3.1 균일 양자화 (Uniform Quantization)

가장 기본적인 방식으로, 값의 범위를 균등하게 나눕니다.

```
알고리즘:

1. 범위 결정: [min, max] = [가중치 최소값, 최대값]
2. 스케일 계산: scale = (max - min) / (2^bits - 1)
3. 양자화: q = round((w - min) / scale)
4. 역양자화: w' = q * scale + min

예시 (4비트, 16단계):
┌────────────────────────────────────────────────────────────────┐
│  원본 가중치: [-0.5, -0.2, 0.0, 0.3, 0.8]                      │
│  범위: [-0.5, 0.8], scale = 1.3/15 ≈ 0.0867                    │
│                                                                 │
│  양자화:                                                        │
│  -0.5 → round((−0.5−(−0.5))/0.0867) = 0                        │
│  -0.2 → round((−0.2−(−0.5))/0.0867) = 3                        │
│   0.0 → round((0.0−(−0.5))/0.0867) = 6                         │
│   0.3 → round((0.3−(−0.5))/0.0867) = 9                         │
│   0.8 → round((0.8−(−0.5))/0.0867) = 15                        │
│                                                                 │
│  양자화 결과: [0, 3, 6, 9, 15]                                  │
│                                                                 │
│  역양자화 (복원):                                               │
│  0 → 0*0.0867 + (−0.5) = -0.500                                │
│  3 → 3*0.0867 + (−0.5) = -0.240                                │
│  6 → 6*0.0867 + (−0.5) = 0.020                                 │
│  9 → 9*0.0867 + (−0.5) = 0.280                                 │
│  15 → 15*0.0867 + (−0.5) = 0.800                               │
│                                                                 │
│  복원 결과: [-0.500, -0.240, 0.020, 0.280, 0.800]              │
│  오차: [0, 0.04, 0.02, 0.02, 0]                                 │
└────────────────────────────────────────────────────────────────┘
```

**Python 구현:**

```python
import numpy as np

def quantize_uniform(weights, bits=4):
    """균일 양자화"""
    w_min, w_max = weights.min(), weights.max()
    scale = (w_max - w_min) / (2**bits - 1)

    # 양자화: 실수 → 정수
    quantized = np.round((weights - w_min) / scale).astype(np.uint8)

    return quantized, scale, w_min

def dequantize_uniform(quantized, scale, w_min):
    """역양자화"""
    return quantized.astype(np.float32) * scale + w_min
```

#### 2.3.2 블록 양자화 (Block Quantization)

전체 텐서에 하나의 scale을 쓰면 정밀도가 떨어집니다. **블록 단위**로 나누어 각각 다른 scale을 적용합니다.

```
┌─────────────────────────────────────────────────────────────────┐
│  전체 양자화 vs 블록 양자화                                     │
├─────────────────────────────────────────────────────────────────┤
│  전체 양자화 (하나의 scale):                                    │
│                                                                 │
│  [0.01, 0.02, 0.03, ..., 5.0, 6.0, 7.0]                        │
│  └─────────────── 하나의 scale ───────────────┘                │
│  → 작은 값들의 정밀도 손실 큼                                  │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│  블록 양자화 (블록별 scale):                                    │
│                                                                 │
│  [0.01, 0.02, 0.03, ...]  [5.0, 6.0, 7.0, ...]                 │
│  └─── scale₁ ────┘        └─── scale₂ ────┘                    │
│  → 각 블록 내에서 최적의 정밀도                                │
└─────────────────────────────────────────────────────────────────┘
```

#### 2.3.3 K-Quant (llama.cpp의 핵심)

llama.cpp가 사용하는 **K-Quant**는 블록 양자화의 발전된 형태입니다.

```
┌─────────────────────────────────────────────────────────────────┐
│  K-Quant 특징                                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 슈퍼블록 구조                                               │
│     ┌─────────────────────────────────────────────┐            │
│     │  Super Block (256 weights)                  │            │
│     │  ┌─────────┐ ┌─────────┐ ... ┌─────────┐   │            │
│     │  │ Block 1 │ │ Block 2 │     │ Block 8 │   │            │
│     │  │ 32개    │ │ 32개    │     │ 32개    │   │            │
│     │  │ scale₁  │ │ scale₂  │     │ scale₈  │   │            │
│     │  └─────────┘ └─────────┘     └─────────┘   │            │
│     │  + 슈퍼블록 scale (d)                       │            │
│     │  + 슈퍼블록 min (dmin)                      │            │
│     └─────────────────────────────────────────────┘            │
│                                                                 │
│  2. 혼합 비트 할당                                              │
│     • 중요한 레이어 (attention): 더 많은 비트                  │
│     • 덜 중요한 레이어: 더 적은 비트                           │
│                                                                 │
│  3. 최적화된 메모리 레이아웃                                    │
│     • SIMD 연산에 최적화                                       │
│     • 캐시 친화적 구조                                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**Q4_K_M 상세 구조:**

```c
// llama.cpp의 block_q4_K 구조체 (단순화)
typedef struct {
    // 슈퍼블록 스케일 (FP16)
    ggml_half d;        // 전체 스케일
    ggml_half dmin;     // 전체 최소값

    // 서브블록 스케일 (6비트씩)
    uint8_t scales[12]; // 8개 블록의 scale과 min

    // 양자화된 가중치 (4비트씩)
    uint8_t qs[128];    // 256개 가중치 (2개씩 1바이트)
} block_q4_K;

// 메모리 사용량: 2 + 2 + 12 + 128 = 144 bytes / 256 weights
// = 4.5 bits per weight (순수 4비트보다 약간 큼, 메타데이터 포함)
```

**역양자화 과정:**

```c
// Q4_K 역양자화 (개념적 코드)
void dequantize_q4_K(block_q4_K * block, float * output) {
    float d = GGML_FP16_TO_FP32(block->d);
    float dmin = GGML_FP16_TO_FP32(block->dmin);

    for (int i = 0; i < 8; i++) {  // 8개 서브블록
        // 서브블록의 scale과 min 추출
        float sc = d * (block->scales[i] & 0x3F);
        float m = dmin * (block->scales[i] >> 6);

        for (int j = 0; j < 32; j++) {  // 블록당 32개 가중치
            int idx = i * 32 + j;
            // 4비트 값 추출 (2개가 1바이트에 패킹)
            int q = (block->qs[idx/2] >> (4 * (idx % 2))) & 0xF;
            // 역양자화
            output[idx] = sc * q - m;
        }
    }
}
```

### 2.4 양자화 타입 비교

| 타입 | 평균 비트 | 블록 크기 | 구조 | 품질 |
|------|----------|----------|------|------|
| **F32** | 32 | - | 부동소수점 | 원본 |
| **F16** | 16 | - | 부동소수점 | 최상 |
| **BF16** | 16 | - | Brain Float | 최상 |
| **Q8_0** | 8.5 | 32 | 단순 블록 | 거의 무손실 |
| **Q6_K** | 6.6 | 256 | K-Quant | 매우 좋음 |
| **Q5_K_M** | 5.5 | 256 | K-Quant 혼합 | 좋음 |
| **Q4_K_M** | 4.8 | 256 | K-Quant 혼합 | 좋음 |
| **Q4_K_S** | 4.5 | 256 | K-Quant | 보통 |
| **Q4_0** | 4.5 | 32 | 단순 블록 | 보통 |
| **Q3_K_M** | 3.9 | 256 | K-Quant 혼합 | 약간 손실 |
| **Q2_K** | 3.4 | 256 | K-Quant | 눈에 띄는 손실 |

> **참고**: `convert_hf_to_gguf.py`는 `f32`, `f16`, `bf16`, `q8_0`, `auto`만 직접 지원합니다.
> K-Quant (Q4_K_M 등)는 변환 후 별도의 `llama-quantize` 바이너리로 추가 양자화해야 합니다.

**이름 규칙:**
- `Q숫자`: 평균 비트 수
- `_K`: K-Quant 알고리즘 사용
- `_M`: Medium - 중요 레이어에 더 많은 비트
- `_S`: Small - 더 공격적인 압축
- `_0`: 기본 블록 양자화

## 3. 변환 파이프라인

### 3.1 전체 흐름

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  LoRA        │     │  HuggingFace │     │    GGUF      │
│  Adapter     │────▶│    Model     │────▶│    Model     │
│              │     │              │     │              │
│ adapter_     │     │ model.       │     │ model.gguf   │
│ model.       │     │ safetensors  │     │              │
│ safetensors  │     │              │     │              │
└──────────────┘     └──────────────┘     └──────────────┘
       │                    │                    │
       │    merge_and_     │   convert_hf_     │
       │    unload()       │   to_gguf.py      │
       └────────────────────┴────────────────────┘
              Python (transformers, peft)    llama.cpp
```

### 3.2 각 단계 상세

#### Step 1: LoRA 병합

```python
from peft import PeftModel

# LoRA를 베이스 모델에 "흡수"
model = PeftModel.from_pretrained(base_model, lora_path)
model = model.merge_and_unload()

# merge_and_unload() 내부:
# W_merged = W_base + (B @ A) * (alpha / r)
# 여기서 B, A는 LoRA의 저랭크 행렬
```

#### Step 2: GGUF 변환

```bash
python convert_hf_to_gguf.py model_path \
    --outfile output.gguf \
    --outtype q4_k_m
```

변환 과정:
1. 모델 구조 파싱 (config.json)
2. 토크나이저 변환 (vocab → GGUF 형식)
3. 각 텐서를 GGUF 형식으로 변환
4. 양자화 적용 (지정된 타입)
5. 단일 파일로 패킹
