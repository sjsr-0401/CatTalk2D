### 1. 환경별 최대 설정

|------|----------|------|--------|-------|-------|------|
| **로컬 (RTX 3060)** | 12GB | polyglot-ko-1.3B | 32 | 64 | 4 | 현재 환경 |
| **Colab Free** | T4 16GB | polyglot-ko-1.3B | 64 | 128 | 8 | 런타임 제한 |

### 2. 파라미터별 효과

#### LoRA Rank (R)
| 값 | 학습 파라미터 수 | 표현력 | VRAM | 권장 상황 |
|----|-----------------|--------|------|----------|
| 8 | ~200K | 낮음 | 적음 | 간단한 스타일 전이 |
| 16 | ~400K | 보통 | 보통 | 기본값, 빠른 실험 |
| 32 | ~800K | 높음 | 많음 | 복잡한 패턴 학습 |
| 64 | ~1.6M | 매우높음 | 매우많음 | 세밀한 행동 제어 |
| 128+ | ~3.2M+ | 최대 | 최대 | 대형 GPU 필요 |

**R을 올리면**: 모델이 더 복잡한 패턴을 학습 가능. 단, 과적합 위험 증가.

#### LoRA Alpha
- **역할**: 학습률 스케일링 (effective_lr = lr * alpha / r)
- **권장**: R의 2배 (R=32면 Alpha=64)
- **높이면**: 학습 변화폭 증가, 빠른 수렴 but 불안정
- **낮추면**: 안정적 학습, 느린 수렴

#### Epochs
| 값 | 학습량 | 과적합 위험 | 권장 상황 |
|----|--------|------------|----------|
| 1-2 | 적음 | 낮음 | 대용량 데이터(5000+) |
| 3 | 보통 | 보통 | 기본값 (500-2000개) |
| 5 | 많음 | 높음 | 소량 데이터(~300개) |
| 10+ | 과다 | 매우높음 | 권장하지 않음 |

#### Batch Size
- **크게**: 안정적 그래디언트, 빠른 학습, VRAM 많이 사용
- **작게**: 노이즈 많음, 일반화 좋을 수 있음, VRAM 적게 사용
- **gradient_accumulation_steps**: 작은 배치로 큰 배치 효과 (메모리 절약)

## LoRA → Ollama 변환 가이드

### 전체 파이프라인 개요

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│  LoRA Adapter   │───▶│  Merged Model   │───▶│   GGUF File     │───▶│  Ollama Model   │
│ (adapter_*.bin) │    │ (safetensors)   │    │ (.gguf)         │    │ (ollama list)   │
└─────────────────┘    └─────────────────┘    └─────────────────┘    └─────────────────┘
     Step 1                 Step 2                 Step 3                 Step 4
    LoRA 학습             모델 병합             GGUF 변환            Ollama 등록
```

### 파일 형식 설명

| 형식 | 확장자 | 설명 | 용도 |
|------|--------|------|------|
| **HuggingFace** | `.bin`, `.safetensors` | PyTorch 모델 형식 | 학습, 추론 (Python) |
| **LoRA Adapter** | `adapter_model.safetensors` | 학습된 LoRA 가중치 | Base model + LoRA = Full model |
| **GGUF** | `.gguf` | llama.cpp 최적화 형식 | CPU/GPU 추론, 양자화 지원 |
| **Modelfile** | `Modelfile` | Ollama 설정 파일 | 시스템 프롬프트, 파라미터 |

### 방법 1: 직접 테스트 (Ollama 없이)

LoRA를 Python에서 직접 로드하여 테스트. 변환 전 품질 확인용.

```bash
cd LoraData
python test_lora.py --lora outputs/cattalk2d_lora_20260124_2056/lora_adapter --interactive
```

**장점**: 변환 없이 바로 테스트
**단점**: 매번 모델 로딩 (1-2분), Python 환경 필요

---

### 방법 2: 자동 변환 스크립트

```bash
cd LoraData
python convert_to_ollama.py \
    --lora outputs/cattalk2d_lora_20260124_2056/lora_adapter \
    --name cattalk-v1 \
    --quantize q4_k_m

# 테스트
ollama run cattalk-v1 "안녕 망고야!"
```

**옵션 설명**:
- `--lora`: LoRA adapter 폴더 경로
- `--name`: Ollama에 등록할 모델 이름
- `--base-model`: 베이스 모델 (기본: google/gemma-2-2b-it)
- `--quantize`: 양자화 타입 (f16, q8_0, q4_k_m, q4_0)
- `--skip-merge`: 이미 병합된 경우 건너뛰기

---

### 방법 3: 수동 변환 (단계별)

#### Step 1: LoRA 병합 (Merge)

LoRA adapter를 base model에 병합하여 단일 모델로 만듦.

```python
# merge_lora.py
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

base_model = "google/gemma-2-2b-it"
lora_path = "outputs/cattalk2d_lora_20260124_2056/lora_adapter"
output_path = "outputs/cattalk2d_lora_20260124_2056/merged_model"

# 모델 로드
tokenizer = AutoTokenizer.from_pretrained(base_model)
model = AutoModelForCausalLM.from_pretrained(
    base_model,
    torch_dtype=torch.float16,
    device_map="auto"
)

# LoRA 적용 및 병합
model = PeftModel.from_pretrained(model, lora_path)
model = model.merge_and_unload()  # 핵심! LoRA를 base에 병합

# 저장
model.save_pretrained(output_path, safe_serialization=True)
tokenizer.save_pretrained(output_path)
```

**결과물**: `merged_model/` 폴더에 완전한 모델 생성
- `model.safetensors` (또는 `pytorch_model.bin`)
- `config.json`
- `tokenizer.json`
- `tokenizer_config.json`

#### Step 2: GGUF 변환

llama.cpp의 변환 스크립트로 GGUF 형식으로 변환.

```bash
# llama.cpp 설치 (최초 1회)
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp
pip install -r requirements.txt

# 변환 실행
python convert_hf_to_gguf.py \
    ../LoraData/outputs/cattalk2d_lora_20260124_2056/merged_model \
    --outfile ../LoraData/outputs/cattalk2d_lora_20260124_2056/cattalk-v1.gguf \
    --outtype q4_k_m
```

**양자화 옵션 비교**:

| 타입 | 크기 | 품질 | 속도 | 권장 용도 |
|------|------|------|------|----------|
| `f16` | 100% | 최상 | 느림 | 품질 중시, VRAM 충분 |
| `q8_0` | 50% | 우수 | 보통 | 균형 잡힌 선택 |
| `q4_k_m` | 25% | 좋음 | 빠름 | **권장 기본값** |
| `q4_0` | 25% | 보통 | 빠름 | 최소 용량, 약간 품질 손실 |

**예시** (gemma-2-2b 기준):
- f16: ~4.5GB
- q8_0: ~2.3GB
- q4_k_m: ~1.5GB

#### Step 3: Modelfile 생성

Ollama 설정 파일 작성.

```dockerfile
# Modelfile
FROM ./cattalk-v1.gguf

TEMPLATE """<start_of_turn>user
{{ .System }}

{{ .Prompt }}<end_of_turn>
<start_of_turn>model
{{ .Response }}<end_of_turn>
"""

SYSTEM """당신은 '망고'라는 이름의 고양이입니다.
- 모든 문장 끝에 '냥'을 붙입니다
- 행동은 (괄호) 안에 표현합니다
- 1-2문장으로 짧게 답합니다
- 고양이답게 츤데레하거나 애교 있게 반응합니다"""

PARAMETER temperature 0.7
PARAMETER top_p 0.9
PARAMETER repeat_penalty 1.1
PARAMETER num_ctx 2048
```

**주요 파라미터**:
- `temperature`: 창의성 (0.1=일관, 1.0=다양)
- `top_p`: 토큰 선택 범위 (0.9 권장)
- `repeat_penalty`: 반복 방지 (1.0=없음, 1.2=강함)
- `num_ctx`: 컨텍스트 길이

#### Step 4: Ollama 등록

```bash
cd outputs/cattalk2d_lora_20260124_2056
ollama create cattalk-v1 -f Modelfile

# 확인
ollama list

# 테스트
ollama run cattalk-v1 "안녕 망고야!"
```

    base_model,
    torch_dtype=torch.float16,
